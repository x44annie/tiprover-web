# Security Policy

## Supported Versions

All actively maintained versions of this project receive security updates.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please send an email to [x44anniedev@proton.me](mailto:x44anniedev@proton.me)

You should receive a response within **48 hours**.

Please include as much of the following information as possible to help us better understand the nature and scope of the potential issue:

- **Type of issue** (e.g. buffer overflow, SQL injection, cross-site scripting, remote code execution, etc.)
- **Full paths** of source file(s) related to the manifestation of the issue
- **Location of the affected source code** (tag/branch/commit or direct URL)
- **Any special configuration** required to reproduce the issue
- **Step-by-step instructions** to reproduce the issue
- **Proof-of-concept or exploit code** (if possible)
- **Impact of the issue**, including how an attacker might exploit it

We prefer all communications to be in **English**.

## What to Expect

| Step | Timeframe |
|------|-----------|
| Initial response | Within 48 hours |
| Status update | Within 5 business days |
| Resolution or mitigation plan | Dependent on severity and complexity |

Once a vulnerability is confirmed, we will work on a fix and coordinate a responsible disclosure timeline with you. We appreciate your patience and cooperation throughout the process.

## Responsible Disclosure

We kindly ask that you:

- Give us reasonable time to investigate and address the issue before any public disclosure
- Avoid accessing, modifying, or deleting data that does not belong to you
- Do not disrupt the availability of the service or exploit the vulnerability beyond what is necessary for the proof of concept

We are committed to acknowledging your contribution if you wish to be credited in the release notes.
