## What You Must Do When Forking

### 1. Keep the License

Your fork **must** be distributed under the EUPL-1.2 (or a compatible license — see below).
You cannot relicense this project under a more restrictive or proprietary license.

### 2. Preserve Copyright Notices

Do **not** remove or alter:
- The original copyright notice (`Copyright (c) 2026 Xannie`)
- Any references to the EUPL-1.2 license
- Notices in source file headers

You must include a copy of the EUPL-1.2 license with every distribution of your fork.

### 3. State Your Changes

If you modify the code, your fork must carry **prominent notices** stating:
- That the code was modified
- The date of modification

A clear note in your README or a `CHANGELOG` entry is sufficient.

### 4. Provide the Source Code

If you distribute a compiled or executable version of your fork, you must also provide — or link to — the corresponding **machine-readable source code**.
This applies even if you host the app as a service (see SaaS rule below).

### 5. Attribution

Give credit where it is due. Acknowledge the original project and author in your fork's documentation or README.

***

## The SaaS / Network Use Rule

EUPL-1.2 **closes the application service provider (ASP) loophole**.

This means: if you run a modified version of this project as a **hosted service** (e.g. a SaaS product, a cloud-hosted note app), you are still required to make the modified source code publicly available.

You cannot take this code, modify it, deploy it as a web service, and keep the changes private.

## What You Cannot Do

- **Close-source your fork** — you cannot distribute modified versions under a proprietary license
- **Remove copyright notices** — all original notices must be preserved
- **Claim original authorship** — you may not misrepresent the origin of this software
- **Use the author's name or branding** for endorsement without explicit permission
- **Offer additional warranties** on behalf of the original author — you may only do so on your own behalf
